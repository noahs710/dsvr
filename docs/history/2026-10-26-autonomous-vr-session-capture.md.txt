# Autonomous VR session capture

Status: user-approved design, 26 October 2026. Implementation is in progress
offline. No live run or deployment is authorized by this document.

## Goal and boundaries

After the one-time startup setting is enabled, the operator should be able to
load into DSR without declaring cases, narrating actions, or pressing a capture
hotkey. The recorder follows verified local-player gameplay epochs and writes
time-correlated raw telemetry plus a machine-readable session index.

The previous case-start-gate design is superseded. The desktop `observer_only`
path cannot meet this scope: it deliberately disables XR and input. Capture must
run in the normal VR LAB path. The recorder adds no gameplay calls/writes,
controller actions, haptics, or input injection, but the ordinary VR mod/game
path is active. No video/audio, save/account metadata, network transfer, or
unsupported scene/outcome labels are added.

## Startup and hook domain

- Add a startup-only, opt-in `autonomous_session_capture` setting, default off
  to prevent unrequested recording. Enabling it is a one-time configuration
  action; no operator action is needed during play.
- Accept it only in a `DSVR_ENABLE_LAB` build with normal VR enabled and
  `observer_only=false`. Refuse incompatible startup combinations with an
  explicit diagnostic; do not silently switch modes. A missing XR input runtime
  is recorded as a capability gap, not fabricated input.
- Install a LAB session-observation hook domain on the accepted VR render frame:
  natural native contacts, interactions, Step dispatches and input-blocker
  observations, plus the new pad/hand telemetry. Do not install the unrelated
  camera/render/constant-upload probes for this mode. The recorder observes the
  effective normal VR path and leaves its behavior unchanged.
- Start automatically after hooks are ready and the verified local-player
  adapter reports a player. Preserve ordinary diagnostics and explicit user
  stop/abort behavior.

## Session, player epochs, and segments

- Generate a unique process session ID and a monotonically increasing player
  epoch. Poll local-player presence on the diagnostics thread. Start an epoch
  on player appearance; close it after 2 seconds of continuous absence. A
  transient absence shorter than the debounce does not split the epoch. If a
  player loads again, automatically begin another epoch under the same process
  session. The title/menu interval is not represented as gameplay coverage.
- Rotate trace files at the writer's 600,000 ms maximum. Each segment has a
  unique path and header carrying session ID, player epoch, segment index,
  QPC frequency/start, UTC start, process identity, mod/schema identity,
  effective capture capabilities, and non-secret capture-relevant config.
  Every normally rotated or player-unload segment must have a genuine footer.
- Maintain an append-only session index beside the trace files. Record epoch and
  segment starts/ends, close reason, QPC/UTC bounds, per-event counts, trace
  state, queue drops/contention, and any measured handoff gap. Never overwrite
  old traces or synthesize a footer. If the game exits/crashes before unload
  closes the current segment, preserve it as incomplete and report that fact;
  previously closed segments remain independently analyzable.
- On a writer I/O error or dropped-event segment, mark the epoch degraded and
  stop claiming complete coverage. Do not spin creating files or delete prior
  evidence. Respect a low-disk reserve and report when capture must stop rather
  than risking unrelated game data.

## Recorded observations

- Preserve existing raw LAB contact batches, interaction activations, Step
  dispatches, input-blocker observations, and trace-health/footer fields. Existing
  native fields remain observations only, not verified hit/block/parry outcomes.
- Record a timestamped event whenever the mapped virtual XInput output changes:
  button bits, triggers, and sticks. These values describe what the mod presents
  to the game, not an unprocessed physical-device signal or player intent.
- Sample each valid tracked grip at no more than 30 Hz, with immediate
  tracking-validity/space-epoch transitions. Include XR-local position,
  orientation, the available grip/tip velocity fields and held squeeze/trigger/
  primary states. Keep XR time and QPC distinct; do not convert to guessed game
  world coordinates or treat pose/gesture as an attack command.
- Use the existing bounded non-blocking trace queue. Any dropped/contended input
  event is included in health counters and invalidates completeness claims.
- Record raw identifiers and state transitions only where already verified.
  Exact map/scene identity and player intent remain unknown unless a separately
  verified source provides them. Do not infer outcomes from callback proximity,
  HP deltas, hand gestures, or input transitions.

## Automatic output and analysis

The session index is the automatic summary: it links every segment/epoch and
reports coverage and loss health without requiring case labels. Extend the
offline `tools/vr_trace.py` analyzer to consume that index and emit a combined
JSON/text report with raw event counts and explicit unknowns. It may correlate
observations by timestamp but must not promote correlation to causation or a
native outcome label. Legacy single-trace analysis remains supported.

## Approved offline test seams

1. Startup/config boundary: accept only normal VR + LAB; reject observer-only,
   non-VR, and non-LAB requests without installing capture hooks.
2. Input-to-trace boundary: mapped pad transitions are emitted once per change;
   hand samples obey the rate cap, preserve XR/QPC/space metadata, and emit
   validity transitions.
3. Lifecycle/artifact boundary: simulated local-player appearance, 2-second
   absence, reappearance, segment rotation, writer failure, and process-exit
   interruption produce the expected files/index/footer states.
4. Public analyzer CLI: synthetic multi-segment sessions produce a truthful
   summary for complete, gapped, dropped, and incomplete sessions; legacy trace
   fixtures continue to pass.

Run focused tests, then rebuild and run full Debug, Release, and LAB Release
CTest suites. Refresh an immutable offline candidate and read-only preflight.
No game launch, deployment, or protected save/install transaction is part of
this implementation task.
