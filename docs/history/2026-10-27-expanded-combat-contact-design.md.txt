# Expanded physical combat, slice 1: continuous blade contact

Date: 2026-10-27. Status: design approved by user section-by-section;
implementation not started. Slice 1 of the expanded-combat scope
(kinetic damage, continuous contact, weight/inertia, two-hand torque,
posture guard, deflect haptics, controller spell/bow aim). Later slices
are named only; this spec covers slice 1.

Target is `DarkSoulsRemastered.exe` (SHA-256
`a45aaa36dd2f6cc151670a639ea5547043cf38ea79ff4178b963c6ed71f98d7b`).
ER natives are reference only. No native damage/defense submission seam
is qualified (`src/core/combat_native.h`, `docs/NATIVE_MELEE_CONTRACT.md`);
nothing here writes game memory or dispatches native events.

## Decisions (user-approved)

- Slice 1 = continuous blade contact only. Kinetic scale rides on it;
  weight/inertia, two-hand torque profiles, posture guard, deflect
  haptics, spell/bow aim are hooked but qualified in later slices.
- Hittable thing = **resolved native hit slots** (AtkParam dummy
  endpoints to world). Victim hurt volumes stay a separate binding.
- Grab signal = free-hand **squeeze held + grip near any point of the
  committed blade segment** (hilt = full two-hand, mid-blade =
  halfsword). Supersedes the 14 cm grip-proximity proxy
  (`src/core/hand_math.h:87`).

## 1. Contact pipeline

- Tracked blade sweep `BladeSweptOverlapsSphereArc`
  (`src/core/combat_math.h:258`) vs attacker hit slots `NativeHitSlot`
  (`src/core/combat_atkparam.h:322`), tested segment-vs-segment
  (`SegmentSegmentDistance`, `combat_atkparam.h:346`).
- Resolve tip/tail dummy ids to world capsules per frame from the
  committed weapon pose; unresolved or stale-model dummy = slot
  invalid; `QualifyContact` stays `slot_resolved=false`. No victim
  spheres invented.
- The bench keeps a parametric capsule approximation explicitly
  labeled as approximation, never as a resolved slot.

## 2. Dummy resolution gate (static work gating the slice)

- Read-only Ghidra probe (`DSRFull`) for the native dummy-id to
  world-position owner of the equipped-weapon model, one leaf at a time,
  no invocation. AtkParam layout (tip `0x2C..`, tail `0x34..` s16 ids)
  is the starting shape, not proof of the owner.
- Resolution is per-equipped-weapon, per-frame, epoch-bound to the
  committed pose; model/equipment change invalidates the cache.
- Fail-closed: lookup miss or stale model refuses the candidate (sphere
  fallback only on explicit caller opt-in).

## 3. Kinetic scale + weight hooks

- Swing energy = head-relative tip speed from the committed pose
  (`BladeKinematics::FeedRelative`, `combat_math.h:169`); walking and
  roomscale never manufacture damage.
- Scale expressed in the native correction domain
  (`NativeCorrectionFromScale`, `combat_atkparam.h:399`): u16 percent
  of the game's own base. Native keeps base/stamina/poise/status/
  hitstop; we only express energy in game terms.
- Weight hook (new offline per-weapon mass/inertia table, equip-param
  transcription): shapes how fast tip speed can rise (daggers ~1:1,
  great weapons lag, need commitment). Weight gates energy, energy
  gates scale; weight never edits damage directly.
- Anti-tunnel sweep + per-target `RehitGate` (280 ms default) stay the
  dedup mechanism.

## 4. Two-hand / halfsword grab

- Attach while free-hand squeeze held and free grip within the envelope
  of the committed blade segment (segment-to-point test); release on
  squeeze release or leaving the envelope. No latch.
- Morphological effect in this slice: support-hand IK target rides the
  blade; two-hand torque profile shapes energy accumulation. Native
  two-hand state/bonus/rows stay unbound; stance intent is published,
  never written.
- Halfsword: effective contact segment shortens to grip-to-grab-point,
  tip speed measured at the grab point. Same `QualifyContact` shape,
  smaller capsule.

## 5. Posture guard, haptics, config, tests, acceptance

- Posture guard: block = shield-side hand still in the head-relative
  envelope AND threat proxy intersecting the shield's committed pose
  (plane/rim), not a hand sphere. Parry = existing flick shape
  (`ShieldGuardTrigger`) intersecting the same coverage. Native
  incoming-attack binding stays open.
- Haptics: keep energy-mapped `HitHaptic` (`combat_math.h:358`); add
  deflect pulse (shorter/sharper than thrust) and two-hand
  attach/detach tick. Fire only from classified bench geometry.
- Config: new `[combat]` keys (mass table path, torque profile,
  halfsword envelope, deflect shape), validated + round-tripped.
- Tests: unit (grab attach/release at segment ends, halfsword
  shortening, weight-gated ramp, resolved-vs-fallback outcomes);
  integration (bench classifies hit/block/parry with new signals, no
  native writes).
- Acceptance: bench geometry green + contracts updated. **B/C native
  gates stay open** until footer-valid B1/H1 captures land.

## Non-goals

Native event submission, victim hurt volumes, incoming-attack binding,
spell/bow aim, any game-memory write, any invented HP/damage numbers.
