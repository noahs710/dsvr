the active owning presentation callback and simulation timing before applying
the requested cap; factory config alone does not unlock it. Pinned PE evidence:
`build/empryo-review/native-rate-static.json`.

`0x1410D5270` assigns the distinct selected root. `0x1410D6D20` mutates saves
**in place**. `0x1410D7E60` mounts `CONTENT_ROOT` at `0x1410D8180`;
`0x1410D7D10` unmounts. Disk operator vtable `0x1414AF4D8` uses open `+A0`,
close `+A8`, truncate `+80`, sync/async write `+D0/+F0`, delete `+108`, rename
`+128`; existing handles/mounts survive simple path replacement. Native UTF-16
strings carry their heap at `+0`, inline/heap storage `+8`, length/capacity
`+18/+20`; allocation can longjmp. No foreign-CRT string swaps or global file hooks.
Sources: `batch-000222`, `000122–123`, `001271`, `001274–277`, `001005–006`.

## 4. API facts that change the implementation

- OpenXR predicts a **display time**, not proof of scene-image age. Locate views
  for that frame's time before rendering and submit matching metadata. Wait/begin/
  end order and `shouldRender` still apply when no scene layer is rendered. [S5]
- `xrWaitSwapchainImage` timeout is a nonnegative **success-class** result but
  does **not** grant image access. Require `XR_SUCCESS`, preserve acquired-image
  state on timeout, and do not release an image never successfully waited on.
  Destruction requires outstanding graphics work completed. Current infinite
  waits/unchecked release results need a real lifecycle audit, not a fake timeout
  wrapper. Correct D3D11 queue ordering can avoid per-frame CPU readback stalls;
  worker completion is not GPU completion. [S5]
- Reuse the game's device only after checking OpenXR adapter LUID and minimum
  feature level. “Any OpenXR runtime” still requires a compatible D3D11 binding. [S6]
- Haptics are output actions; a newer event replaces an unfinished event on the
  same action. Coalesce/prioritize feedback, don't restart vibration every draw;
  stop on focus loss and disable. Standard vibration cannot resist a real hand. [S7]
- Pinned ReShade SDK v6.6.2/API18 commit
  `7d13ead8f630d045b9e7e2ac2ce18b2e7e5b25c3`: D3D11 Present event precedes effects
  and filters TEST Presents (`source/dxgi/dxgi_swapchain.cpp:939–991`). A real
  host binary/order remains unverified. UI capture requires DSR draw evidence. [S8]
- Prefer a standard Windows lab account over native save-string RE: current-user
  known folders follow its initialized profile, and tokens/DACLs provide an
  independent file boundary. Steam/game must share OS user/elevation; Windows
  users don't isolate Steam account/cache/achievements or guarantee per-user XR
  readiness. Validate the actual process and save paths in a desktop-only smoke
  test before modded VR runs. Store metadata currently omits DSR Cloud, not proof
  that all installed client synchronization is absent. [S10–S13]
