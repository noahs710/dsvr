## Goal

Implement the approved spec
`docs/superpowers/specs/2026-10-16-dsvr-unblock-parallel-design.md`: build
the five blocked DSVR areas (motion blur, UI suppression, true stereo,
AFR, physical combat) as parallel isolated tracks, integrate them one at
a time in order T1-T5, and keep every user-facing claim honest until its
headset gate in `docs/VERIFICATION_RUNBOOK.md` passes.

## Success Criteria

- Each track lands with a test that failed before its change and passes
  after; the full offline gate (`pwsh -File tools\auto_verify.ps1`,
  currently 62/62 CTest + doctor) is green after every integration.
- No fake stereo and no combat substitute ships: stereo refuses rather
  than duplicating mono; combat applies no damage without a qualified
  native ABI.
- Every new behaviour is behind a default-off flag; mono, visible UI,
  and non-damaging behaviour remain the fallback on any refusal.
- Home-menu capability text matches reality after each integration
  (available / experimental default-off / not yet bound).
- Headset verdicts are unchanged by this plan alone; they move only
  through the verification runbook afterwards.

## Approach

Five tracks own only their new files and tests. One integrator (the
implementing agent, sequentially) edits shared files (`src/common/
config.*`, `src/setup/setup.cpp`, `src/core/mod_menu.cpp`, CMake lists)
in track order and runs the full gate after each track. Native targets
are pinned-build verified and signature-gated, writes happen on the
owning thread through guarded access, observer mode refuses writes, and
any mismatch degrades to current behaviour with one log line. Alternatives
rejected in the spec stay rejected: no offset-mono stereo, no HP edits,
no unguarded offsets, no early native write for blur or UI.

## Steps

### T1 - Motion-blur enforcement (first integration)

1. Identify the live blur preference from the installed game files
   (read-only). If the key/encoding is ambiguous, stop T1 writes and
   record the ambiguity; never guess.
2. Add failing tests first in `tests/test_blur_enforcement.cpp`
   (CTest name `blur_enforcement`) for the
   pure state machine in new `src/common/blur_state.h`: original ->
   forced-off -> restored over fake file bytes, double-install
   idempotence, missing-file default.
3. Integrator: add `force_disable_motion_blur` and Setup-owned
   `motion_blur_original` to config load/save, wire record/force on
   install and restore on uninstall in `src/setup/setup.cpp`, and show
   original/forced/current in doctor output.
4. Validate: build `test_blur_enforcement`, run
   `ctest --test-dir build -C Release -R "blur|config"`, then full gate.

### T2 - UI suppression qualification, then gated hide

1. Derive the pinned HUD/UI target from the existing GPU capture and
   corpus; write the qualification result (target, signature, refusal
   behaviour) as evidence under `build\verification\`.
2. Add failing tests first in `tests/test_ui_suppression.cpp` for the
   hide/show state machine in new `src/core/ui_suppression.h`:
   immersive -> theater -> immersive, signature-mismatch refusal, DSVR
   menu reachable in both modes.
3. Only if qualified: integrator connects `hide_ui_in_vr` to the gated
   adapter; otherwise the track integrates the state machine and tests
   with the feature still labelled not bound, and says so.
4. Validate: `ctest -R "ui_suppression|menu"`, then full gate.

### T3 - True stereo production caller

1. Add a failing caller test (`tests/test_stereo_caller.cpp`, fake XR
   following `tests/test_xr_mono_recovery.cpp` patterns): one submitted
   eye pair advances simulation exactly once; stale token and
   wrong-thread end are refused; mono fallback engages on refusal.
2. Wire `XrBeginNativeStereoFrame`/`XrEndNativeStereoFrame`
   (`src/core/xr.cpp`) into the production render path behind
   `stereo_enabled` (default off). If two real eye renders cannot be
   produced, refuse and continue mono; document every remaining pose/
   camera assumption in code comments.
3. Integrator: config key, Rendering panel label (experimental, default
   off), metrics unchanged for mono.
4. Validate: `ctest -R "stereo|xr_"`, then full gate.

### T4 - AFR on real stereo (after T3 only)

1. Record freshness definitions (eye age in frames at submission) at
   the top of `tests/test_afr_policy.cpp`, then add failing tests for
   the pure alternation policy in new `src/core/afr_policy.h`.
2. Integrate alternating submission behind `afr_enabled` (default off),
   selectable only while stereo is active; add per-eye freshness to
   RenderMetrics. AFR with stereo inactive must refuse.
3. Validate: `ctest -R "afr|stereo|xr_"`, then full gate.

### T5 - Combat contact classification (damage stays gated)

1. Add failing tests first in `tests/test_combat_contact.cpp` for the
   classifier in new `src/core/combat_contact.h` over recorded
   kinematics: hit, miss (no event), shield block, parry window, rehit
   window, target despawn, support-grip attach/detach.
2. Connect classification to the bound equipment read and existing grip
   profiles; log events and leave haptics hooks inert. Apply no damage:
   `CombatNativeLimitation()` text stays accurate.
3. Integrator: Combat panel shows classification status separately
   from the still-blocked damage status.
4. Validate: `ctest -R "combat|weapon_grip"`, then full gate.

### Final integration pass

- Re-run the full gate, refresh `dist\DSVR-latest` through the gated
  script, run `tools\verify_preflight.ps1`, and update the runbook
  blocked table only where a track's status genuinely changed.
- Hand off to headset verification (runbook segments 1-10). Do not
  change any PASS/FAIL verdict in this pass.

## Validation Plan

- Per track: the track's new test red before, green after (commands in
  each step), plus the named existing-test regex still green.
- Per integration: `cmake --build build --config Release`, full CTest,
  `DSVR-Setup.exe --doctor`, all via `pwsh -File tools\auto_verify.ps1`.
- Safety evidence: install/uninstall hash comparison for T1, refusal
  logs for gated tracks, observer-mode write-block tests.
- Headset checks are explicitly out of scope here; they are the
  runbook's job after this plan completes.

## Risks / Open Questions

- T1 depends on identifying the live blur key/encoding; ambiguity stops
  that track's writes (by design), other tracks continue.
- T2 and T5-damage may end this plan still BLOCKED if their native
  targets cannot be qualified offline; integrating tests and honest
  labels is the correct outcome, not a failure to hide.
- T3 may prove the draw boundary needs a native run before any caller
  can work; then T3/T4 integrate only the refusal-tested scaffolding
  and stereo stays experimental-off. Open questions: none requiring the
  user; every unknown above has a refuse-and-record default.
